## 1. 产品定位与设计原则

衔枝新前端从「引擎控制台」升级为「记忆书」。它不再是给开发者调试的仪表板，而是给用户 daily use 的陪伴界面。

**核心设计原则：**

1. **叙事优先**：首页是「今天的故事」，不是技术指标。
2. **情感层隔离**：日记、心迹、便签、印章都不直接污染引擎编织层，但用户的回应会通过影子碎片进入引擎视野。
3. **移动端优先**：单手握持体验优先，桌面端是扩展。
4. **仪式感**：印章与玻璃珠是情感封存仪式，不是功能按钮。
5. **人话写一切**：ACTIVE/DORMANT/SILENT 变成「进行中 / 暂时搁置 / 沉默中」，conviction 叫「确信度」或直接展示进度条。

│       └── 2026-08-24_001.json    # 便签，JSON 格式
└── stamps/
    └── {userId}/

  id: BeadType
  name: string                 // 珠子名
  color: string                // CSS gradient
  texture: 'clear' | 'frosted' | 'cat_eye' | 'glitter'
  whisper: string              // AI 回礼语
  source: string               // 署名
}

// 印章定义（全局常量）
interface StampDefinition {
  id: StampType
  name: string                 // 中文名
  motto: string                // 环形铭文
  mood: string                 // 心境描述
  baseColor: string            // 蜡滴底色
  emblemColor: string          // 图腾线条色
  rimColor: string             // 铭文/边缘色
  eligibleBeads: BeadType[]   // 该印章可能回赠的珠子池
}

// 用户的一次盖印记录
interface StampRecord {
  id: string                   // stamp-{timestamp}-{random}
  type: StampType
  beadType: BeadType           // 实际回赠的珠子类型
  noteId: string               // 关联便签 ID
  stampedAt: string            // ISO 8601
  userNote?: string             // 用户随笔（可选）
}

// 玻璃珠罐条目（用户收集的珠子）
interface JarEntry {
  id: string                   // bead-{timestamp}-{random}
  stampType: StampType
  beadType: BeadType          // 珠子类型引用
  noteId: string               // 由哪条便签产生
  date: string                 // YYYY-MM-DD
  beadName: string             // 冗余珠子名，方便展示
  stampedAt: string            // ISO 8601
  memoPreview?: string         // 便签前 50 字摘要
}

// 用户印章总览（per-user 存储）
interface UserStampState {
  records: StampRecord[]
  jar: JarEntry[]
  lastStampedAt?: string
}

- 8 枚印章 × 每枚 3 颗候选珠子 = 24 种组合
- 12 颗珠子被多枚印章共享，形成交叉映射
- AI 在候选池中选择，既有规律又有惊喜

### 4.3 交互流程

**阶段 1：Hover · 微风浮起**
- 触发：鼠标/手指悬停印章托盘
- 表现：印章上浮 10px、rotateX(10deg)、底部柔光、名称淡入

**阶段 2：Inspect · 3D 端详**
- 触发：点击印章
- 表现：
  - 托盘下沉隐藏
  - 黑色遮罩 + blur
  - 印章飞到视窗中央，沿 Y 轴翻转 720°
  - 放大到 280-300px 高清版
  - 2 秒后提示「再次点击铜章，盖下这枚印章」

**阶段 3：Stamp · 重力坠落**
- 触发：端详模式下再次点击
- 表现：
  - 印章从视窗中央坠落到便签右下角
  - 便签触发 cardShake（0.45s 微震）
  - 压痕处涟漪扩散
  - 印章留在便签上，带扫光效果

**阶段 4：Bead · 玻璃珠回礼**
- 触发：盖印落地后 0.4s
- 表现：珠子从底部浮出，显示珠子名、whisper、source

**阶段 5：Jar · 永久收藏**
- 触发：盖印完成后
- 表现：珠子存入珠子罐，首页/珠子罐面板更新

### 4.4 后端 API

#### `POST /v1/notes/:noteId/stamp`

用户对便签盖印。

**请求体：**

```json
{
  "type": "branch",
  "userNote": "（可选）用户随笔"
}
```

**后端行为：**

1. 校验 note 存在且状态允许盖印（`read` / `responded`）
2. 校验 `type` 在 `STAMP_REGISTRY` 中
3. 调用 `selectBead(stampType, userId, note)` 选择珠子（见 4.5 节）
4. 更新 note.stamp
5. 生成 `StampRecord` 和 `JarEntry`
6. **创建影子碎片**，让引擎知道用户今天对这条便签的态度
7. 持久化到 `stamps/{userId}/beads.json`
8. 返回更新后的 note + bead 信息

**响应：**

```json
{
  "note": { /* 更新后的 Note */ },
  "bead": {
    "id": "jade_water",
    "name": "翡翠水波珠",
    "color": "linear-gradient(135deg, #4A6B5D, #8FB8A0)",
    "texture": "clear",
    "whisper": "「你衔着细枝飞过今天，巢又稳了一层。」",
    "source": "κόραξ → Σελήνη · 衔枝之珠"
  },
  "selection": {
    "type": "branch",
    "beadType": "jade_water",
    "reason": "用户最近三天收集的珠子以冷色调为主，这枚衔枝章选择翡翠水波珠以延续平静感。"
  },
  "jarCount": 12
}
```

#### `GET /v1/stamps`

取用户所有盖印记录（用于珠子罐）。

**响应：**

```json
{
  "records": [ /* StampRecord[] */ ],
  "jar": [ /* JarEntry[] */ ],
  "total": 12
}
```

取最近 N 条盖印记录，用于注入 AI 上下文。

**参数：**

| 字段 | 类型 | 必填 | 说明 |

### 4.5 玻璃珠选择算法（AI 的选择）

盖印时，珠子不是固定的一对一回礼，而是来自该印章的候选池。后端通过选择算法决定最终回赠哪一颗。

**候选池：**

```typescript
const candidates = STAMP_REGISTRY[stampType].eligibleBeads
// 例如 branch 的候选池：['jade_water', 'morning_dew', 'mother_pearl']
```

**选择策略（可配置）：**

```typescript
function selectBead(
  stampType: StampType,
  userId: string,
  note: Note,
  recentEntries: JarEntry[]
): BeadType {
  const candidates = STAMP_REGISTRY[stampType].eligibleBeads

  // 策略 1：避免最近重复（默认）
  const recentTypes = recentEntries.slice(-14).map((e) => e.beadType)
  const deduped = candidates.filter((b) => !recentTypes.includes(b))
  const pool = deduped.length > 0 ? deduped : candidates

  // 策略 2：基于便签内容关键词匹配（轻量规则）
  const noteText = note.content.toLowerCase()
  const keywordMap: Record<string, BeadType[]> = {
    '累': ['amber_honey', 'frosted_salt'],
    '睡不着': ['gray_moonstone', 'lapis_depth'],
    '开心': ['coral_pulse', 'jade_water'],
    '谢谢': ['aquamarine_drop', 'mother_pearl'],
    '不甘心': ['blood_amber', 'obsidian_gold'],
  }

  for (const [keyword, matched] of Object.entries(keywordMap)) {
    if (noteText.includes(keyword)) {
      const intersection = pool.filter((b) => matched.includes(b))
      if (intersection.length > 0) {
        return intersection[Math.floor(Math.random() * intersection.length)]
      }
    }
  }

  // 策略 3：随机选择
  return pool[Math.floor(Math.random() * pool.length)]
}
```

**AI 选择感：**
- 从用户视角，AI 似乎「看懂了我的心情」才选了这颗珠子
- 从实现角度，是规则 + 随机 + 去重的组合
- 后续可接入轻量 LLM prompt 让选择更有叙事感

### 4.6 印章的影子碎片策略

当用户盖印时，**默认创建**一条影子碎片：

```typescript
const shadowFragment: Fragment = {
  id: `sf-stamp-${stampRecord.id}`,
  body: `〔印章：${stampDefinition.name}〕${stampDefinition.mood} · 回赠 ${selectedBead.name}`,
  shadow: true,
  source: 'stamp',
  noteId: note.id,
  // 不登记线索、不参与认识抽取、不参与碰撞
}
```

**默认创建**，因为：
- AI 在 `getContextPacket` 检索时能看到「用户对 XX 便签盖了 XX 章」
- 不污染编织层（shadow 过滤）
- 让 AI 后续对话可以引用：「你昨天给『别熬太晚』那枚便签盖了衔枝章，收到一颗翡翠水波珠」

### 4.7 AI 对印章的可见性

在 `getContextPacket` 返回的叙事上下文包中，增加 `recentStamps` 字段：

```typescript
interface ContextPacket {
  // ... 已有字段
  recentStamps: {
    type: StampType
    beadType: BeadType
    beadName: string
    date: string
    notePreview: string
  }[]
}
```

宿主 agent 的 system prompt 中可提示：

> 最近 7 天内用户盖过的印章代表他当时的心境。同一枚印章可能回赠不同的珠子，珠子的 whisper 是 AI 想对他说的话。提及这些印章时，可以用珠子 whisper 的意象回应，但不要刻意强调。

## 5. 情感层：日记、心迹、便签

### 5.1 日记 Journal

**存储格式**：Markdown 文件，每用户每日期一个文件。  
**路径**：`server/data/journal/{userId}/{YYYY-MM-DD}.md`

**生成时机：**
- 主路径：reflect 完成后触发
- 备选：每日 23:00 定时任务兜底

**API：**

- `GET /v1/journal?userId=&date=`
- `GET /v1/journal/range?userId=&from=&to=`
- `POST /v1/journal/generate`

### 5.2 心迹 Soliloquy

**存储格式**：Markdown 文件，每用户每日期一个文件。  
**路径**：`server/data/soliloquy/{userId}/{YYYY-MM-DD}.md`

**生成时机：**
- reflect 流程末尾，独立步骤
- 失败 catch 不影响 reflect 主流程

**API：**

- `GET /v1/soliloquy?userId=&date=`
- `GET /v1/soliloquy/recent?userId=&limit=`

### 5.3 便签 Note

**存储格式**：JSON 文件。  
**路径**：`server/data/notes/{userId}/{YYYY-MM-DD}_{NNN}.json`

**API：**

- `GET /v1/notes/current?userId=` —— 取当前应展示便签
- `GET /v1/notes?userId=&page=&limit=` —— 历史列表
- `POST /v1/notes` —— 宿主写入
- `POST /v1/notes/:id/read` —— 标记已读
- `POST /v1/notes/:id/respond` —— 用户回应
- `POST /v1/notes/:id/stamp` —— 用户盖印

**首页展示规则：**
- 始终展示最新一条非 archived 便签
- 新便签生成时，旧便签自动 archived
- 若无便签，展示空状态

### 5.4 ContextAnchor / 影子碎片

**问题**：便签本身不进引擎，用户回应时引擎看不到原文。

**方案**：

```typescript
// 1. 用户回应便签
POST /v1/notes/:id/respond
{ "text": "你说得对，我今晚早点睡", "mood": "被触动了" }

// 2. 后端创建影子碎片
const shadowFragment: Fragment = {
  id: `sf-${note.id}`,
  body: note.content,
  shadow: true,
  source: 'note',
  noteId: note.id,
}
state.fragments.push(shadowFragment)

// 3. 自动 ingest 用户回应，附带 contextAnchor
engine.ingest("你说得对，我今晚早点睡", {
  contextAnchor: {
    type: 'note-response',
    shadowFragmentId: shadowFragment.id,
    notePreview: note.content.slice(0, 40),
  }
})
```

**引擎过滤点：**

- 碰撞判定跳过 shadow
- 线索登记跳过 shadow
- 认识抽取跳过 shadow
- 向量召回候选排序跳过 shadow
- `getContextPacket` 检索可选包含 shadow
- `fragView` 展示时保留上下文
