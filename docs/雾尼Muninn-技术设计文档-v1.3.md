## 1. 定位与问题定义

### 1.1 问题：碎片化原罪

所有现有记忆系统（mem0 / Zep / Letta / Amory，以及独立开发圈的个人记忆成品）的输出单位都是**孤立碎片**——事实条目、事件桶、检索 top-k。治理得再好的碎片仍是碎片。人类记忆的本质不是存储而是**编织**：我记得你，不是因为我存了一打关于你的卡片，而是因为我心里有一个连续的你。

### 1.2 三个未解决问题

1. **联系**：碎片之间没有叙事结构（伏笔、推进、闭合）
2. **动态**：对用户的理解不随新证据演化（追加式画像只会变长不会变）
3. **持续**：会话/时间断裂后，理解裸露出断层

### 1.3 定位声明

* **不是**人格画像（危险命名，弃用）→ 是 **Adaptive User Model / 长程理解层（Longitudinal Understanding Layer）**

* 核心认识论立场（产品级卖点）：**「我知道我对你的理解可能错，并且我能修正」**

* 情感与陪伴是首发垂直场景；引擎本身面向一切长程 agent（教育、医疗陪护、客户关系、NPC、个人助理）

## 2. 总体架构：三层叙事记忆引擎

```
┌─ 认识层（lifetime periods / 长程理解层）───────────┐
│  对人/关系/主题的活叙事文档                          │
│  增量重述 + 版本史 + 全套防漂移机制                  │
├─ 线索层（general events / 草蛇灰线系统）────────────┤
│  开放线索登记簿：未闭合状态的追踪                    │
│  ACTIVE / DORMANT / SILENT 三池                     │
│  merge / split / 反刍节律                           │
├─ 碎片层（specific episodes）───────────────────────┤
│  事件桶：VAD 情感坐标 + 情绪调制衰减                  │
│  （成熟机制复用层，非本项目创新主体）                 │
└────────────────────────────────────────────────────┘
```

**检索输出**：不是 top-k 卡片，而是「叙事上下文包」——相关碎片 + 所在线索位置 + 当前认识状态。

## 3. 碎片层

* 事件桶：标题 + 正文 + YAML 元数据（Markdown 存储路线）

* **VAD 情感坐标**（valence / arousal / dominance 三维连续值，非离散标签）

* **情绪调制衰减**：衰减率 = f(时间, 唤醒度)，高唤醒记忆衰减更慢（心理学依据：emotion-enhanced memory / flashbulb memory）

* 本层的直接基础是主创 2026-05-23 构建并实跑至今的 memory\_system：遗忘曲线公式（R = e^(-t/S)）、五维度半衰期、VAD 情绪时间线、Feel 反思、频率/层次双蒸馏——其中**层次蒸馏（日记聚类生成人生阶段）正是认识层的理念雏形**，本方案将其升级为完整的叙事层。数月真实使用数据与迭代经验在案。**创新主体不在此层**

## 4. 线索层：草蛇灰线系统

### 4.1 核心 reframe

线索的单位不是「事件」，而是**未闭合的状态**。 「攒钱买硬盘」登记的不是这句话，是它悬置的问题——「存储/设备焦虑是否解除」。

### 4.2 Thread Schema v2

```
Thread {
  id
  open_question              // 悬置的问题（登记时由 LLM 提取）
  synthetic_sentences: {
    abstract_floor: []       // 对 open_question 的抽象改写，t=0 起存在，召回兜底
    concrete_guesses: []     // 「如果回收会长什么样」的具体猜测，随推进/merge/split 重生成
  }
  dragon_vein_value          // 龙脉值：当前连接潜在叙事空间的广度（描述现在，不预测未来）
  emotional_weight           // 缓存值，由 event_history 派生，不直接参与合并运算
  event_history: []          // 按时间戳排列
  status: unresolved | resolved | dissolved | abandoned | superseded | merged
  closure_reason             // 自由文本；dissolved 必须交代「为什么不再成立」
  lineage: { parent_ids: [], child_ids: [] }
}
```

### 4.3 登记：宽进严升

* 准入判据：「是否隐含一个尚未闭合的状态」（VAD 情感强度过阈值 + 状态非终态，复用现有权重，不另起分类器）

* 稳定属性陈述（「她一直抑郁」无变化预期）→ 画像属性，不占线索位

* **龙脉值绝不参与登记准入**——它只能管「看哪里」（注意力权重/搜索优先级/推理预算分配），不能管「记不记」

* 设计债务①：龙脉值冷启动死循环——新边的形成发生在碰撞里，与龙脉值排序无关；龙脉值只做相对排序，不设绝对门槛

### 4.4 合成句双层结构（HyDE 迁移）

* 登记时用一次 LLM 调用生成「回收长相」的合成猜测句，embedding **合成句而非原句**

  * → 三个月后「旧电脑终于退役了」与合成句天然接近，尽管与「硬盘」零重合

* **双层衰减**：具体层（concrete\_guesses）的命中质量随时间下降；线索开得越久且无推进，检索权重逐渐向抽象层（abstract\_floor）倾斜

* 抽象层拉高召回也拉高模糊撞车风险 → 假阳性防线在 LLM adjudication 层，不在向量层

* **重生成「一个函数、四个触发点」**：推进事件改变预期回收形状时（增量补充，旧假设空间保留不推翻）、merge 后、split 后、反刍扫过久无推进线索时（抽象层加权）。反刍是节拍器，不是无脑执行开关

### 4.5 三池管理

| 池            | 定义                                     | 碰撞策略                                        |
| ------------ | -------------------------------------- | ------------------------------------------- |
| ACTIVE（≤10条） | 近期频繁提及 / 情感权重大 / 强时间锚点                 | 实时碰撞，100%                                   |
| DORMANT      | 暂时不用（如三个月前买硬盘失败）                       | **绝不脱离碰撞**（脱离等于死亡）：低频扫描（随机抽样+事件触发）          |
| SILENT       | **回避型高权重**（如父亲的病）：用户不主动说、情感权重极高、不因沉默降权 | 不参与日常召回；**触发器唤醒**（状态模型检测到相关模式即唤醒，如「家庭责任模式」） |

* SILENT 数据结构：`importance: 0.95, mention_frequency: 0.05, avoidance_signal: 0.9, trigger_threshold: low`

* 设计债务②：avoidance\_signal 是负证据推断——「不想提」与「不重要所以不提」数据上同构。判 SILENT 需三信号齐备：曾高频提及后骤停 + 提及时高情感强度 + 相关话题出现时话题转移。接受一定虚警率

### 4.6 碰撞机制

1. **向量预筛**：新事件 vs 活跃池合成句（非原句）+ 情境标签物理隔离（【物欲/生活规划】与【当下感官/饮食】分池）
2. **结构化校验**：候选与线索的核心实体类型是否真实重叠（防同类词撞车，如两条不相关「攒钱」线索）
3. **一次 LLM 打包判定**：新事件 + top-k 候选悬置问题，逐条判断呼应类型（推进/回收/反转/无关）。调用次数只与 k 相关，与线索总数 n 无关
4. **判定问法去诱导化**：不问「这俩相关吗」，问——

   * **「Did event B modify the trajectory implied by thread A?」**（核心转向：不寻找相似，寻找状态变化）

   * resolved 问：「这件事回答了悬置问题吗」

   * dissolved 问：「这件事有没有让悬置问题本身不再成立，而不是被回答」
5. **弱信号软链接**：单次弱信号不下死判，留作待印证软链接，二次信号加固再转正
6. **残余漏报**：不指望实时抓——放反刍节律做更贵更从容的联合推理。**草蛇灰线本来就是回头看整条脉络才显影的**

### 4.7 状态机（六态）

| 状态         | 触发                               | 可逆性                                               |
| ---------- | -------------------------------- | ------------------------------------------------- |
| unresolved | 默认开放态                            | —                                                 |
| resolved   | 事件回答了悬置问题                        | 难翻案（锚定世界里确实发生的事）                                  |
| dissolved  | 事件使问题前提不再成立（上云→存储焦虑消失）           | 难翻案                                               |
| abandoned  | 久无推进 + 龙脉值衰减至阈值下（仅反刍被动判定）        | **廉价可重激活**：不进死档，降级二级召回层——热路径扑空才扫归档层。**伏脉千里的工程落地** |
| superseded | 框架被替换而非并入（split 后父线索；或被更好提法整个取代） | —                                                 |
| merged     | A、B 并入 M 后的专属终态（其他五态语义全不合，必须有）   | 指向 M                                              |

* `closure_reason` 自由文本：系统回溯时能说清「这事解决了」还是「这事你好像不再纠结了」——**这两句话说给一个真人听，分量完全不一样**

### 4.8 merge / split 与 lineage

**merge 触发**：新碎片在一次批量分类调用中同时判「推进」两条线索 → 共同命中作为候选信号（零额外成本）→ 单独 adjudication 调用拿两条线的**完整历史**判定（「攒钱买硬盘」与「想换电脑」被认出是「设备升级」，靠的是历史里反复出现的同一种烦躁，不是字面像不像）

**merge 合并规则**：

* open\_question 重写概括，不拼接

* synthetic\_sentences **整套重生成**而非取并集（合并本身可能打开两边都没想到的回收路径）

* 龙脉值：1-(1-a)(1-b) 饱和式合并 + 一次性小额加成（防通胀）

* 情感权重：不合数——event\_history 并集后按原聚合逻辑（带时间衰减）重算

* event\_history：并集按时间戳重排

**split 触发（镜像结构）**：热路径分类调用搭车多问一句「本次推进与近期推进是延续，还是互不干涉的平行分支」（近零成本）→ 「疑似分支」标记积累到量后，反刍阶段问「这些事件还共享同一个回收条件吗」（「修仙连载」回收不会让「人外新坑」回收=分化完成证据）

**split 规则**：分裂点前历史共享，之后各自独立；龙脉值与情感权重**复制而非对半分**——龙脉分叉时两条都还是完整的龙脉，不是瓜分定量池

**lineage 统一**：parent\_ids = 从哪来，child\_ids = 变成了什么。「这两件事你以前是分开想的」——顺着 lineage 走就行，**这本身就是一次鸾胶续弦**

## 5. 认识层：长程理解层

### 5.1 改写式，不是追加式

| <br /> | 追加式（Generative Agents reflection） | 改写式（本方案）                  |
| ------ | --------------------------------- | ------------------------- |
| 比喻     | 日记                                | 人的自我认识                    |
| 结构     | 事件₁ 事件₂ 洞察₁ 洞察₂……                 | 过去理解 A → 新证据重新解释 → 现在理解 B |
| 优势     | 稳定                                | 能够成长                      |
| 缺点     | **不会死亡**（十年前的「喜欢玩游戏」十年后还在）        | 可能漂移                      |

**叙事链（对外标准表述）**：普通记忆不更新→僵化；改写式更新→可能漂移→需要审计机制→形成**可控演化**。改写式系统最大的风险是它**拥有解释过去的权力**——因此我们设计了版本史、证据锚定、反证搜索和周期审计：让「会变化」变成可追踪的变化，而不是随机漂移。

### 5.2 防漂移机制组

**证据锚定**：认识文档每条论断必须引用支撑碎片 ID，改写留版本史。
（已知局限：锚定证明「引用的碎片存在」，不证明「没引用的碎片被公平考虑过」——故需下条）

**反证搜索（确认偏误对策）**：每条既有论断重写前，先生成**反面假设**，拿反面假设检索碎片库找反证（HyDE 反用）。命中反证→强制 adjudication：模型必须显式回应——改论断、加限定语、或写清「为什么这条反证不足以推翻」，**说明留痕，不许悄悄吞掉**。
设计债务③：自我对抗天花板——反面假设仍由同一模型生成，可能只造得出稻草人反证。缓解：异源生成（不同模型/温度/persona 组团唱反调）。根治不了，写进局限性。

**conviction 分数**：论断不用布尔，挂置信分。反证每次被「解释掉」，conviction 仍**小幅衰减**——反复被挑战的论断更快被下轮反刍推翻重审，不因「每次都辩赢」固化成教条。

**盲推导审计（渐进漂移对策）**：反刍节律中定期抽样——不给模型看文档当前版本，只给原始碎片库，从零重新生成理解，与现有版本对照，分歧大=漂移信号。

* **触发者必须是系统排程，不能等用户发起**——人和系统活在同一套缓慢扭曲的叙事里时，双方都不会觉得有必要审计。这正是渐变问题的本质，责任不能交给当事人

* 漂移定位（诚实版）：按时间戳重建「某历史版本当时可见的碎片子集」，对该子集盲推导，与该版实际文本比对。**若「版本越老、与当前分歧越小」的单调假设成立**，可用探针二分，**log(n) 次调用**圈定漂移区间，命中版本对后再以反证搜索核验（分歧确实由该区间碎片引发，而非 judge 噪声）。但漂移对版本距离**并不保证单调**——一次反刍的自我修正会让分歧中途回落，此时二分前提破裂，退化为**分段扫描**（固定步长逐段比对，成本高于 log(n) 但有界）。当前实现只有检测与标记，定位未做——先把「是否漂移」答对，再谈「在哪里漂移」

* 设计债务④：需 null model——同一批碎片多次盲推导建立自然方差基线，超基线的分歧才算漂移信号，否则审计系统自己虚警

* 分歧幅度本身是独立信号：过大直接标记等用户来看（接 §5.4 可见性出口）

### 5.3 自我实现预言的断路器（四联装）

叙事闭环——认识影响回复、回复影响行为、行为「验证」认识——没有单一断点，四环同拆：

1. **belief / policy 解耦**：「她拖延」不自动触发「催她」。论断与干预之间是必须独立论证的决策层
2. **endogenous 标记**：系统干预催生的行为不算验证该论断的干净证据（被催三次才交，证明的是催促起了作用）。凡系统自己插手造成的行为样本，重验证时降权甚至剔除
3. **对照窗口**：定期主动不干预，看论断在系统完全不插手时是否仍成立——给系统自己的信念留一次干净的反事实检验

   * 设计债务⑤：对照窗口有伦理代价（明知可能受伤也不提醒）。需风险分级——高风险事项不参与对照
4. **语言去定性化**：不写「她是拖延的人」（人格定性），写「Q2 期间 X 项目的三次 deadline 均延后」（带情境与时间窗的观察）。定性化表述最容易被系统和她自己都当成固定本质

### 5.4 用户权利：三根独立的轴

**可见度**：默认**全透明**。这套系统的出发点是了解和陪伴，前提是关系——不可见就是监控，这条不退让。最锋利的论断可讲究呈现**时机**（带证据链、在容得下反驳的对话场景浮现，而非干巴巴扔进 dashboard）——但这是 delivery 问题不是 access 问题，不能借「怕她难受」把可见度偷偷调低，**那是把 paternalism 从后门带回来**。

**可编辑度（真正的分野）**：

* **事实层（碎片）不可改**——改了就是改写历史（设计债务⑥：允许「本人修正标注」，不改原文但追加 correction annotation）

* **诠释层（碎片「意味着什么」）用户有最终解释权**——对一个人内心状态的诠释，本就没有脱离本人证词的客观真相可以仲裁。系统至多重证据摆清楚，不能凌驾于她的自我认知权威之上。**这是硬边界**

**删除之后（contested 状态）**：真忘掉不对（下轮反刍碰上同样碎片簇还会重新生成同一句话，她得没完没了跟自己的心理侧写打地鼠）；表面删除后台照用也不对（只是给背着她写的档案多蒙一层布）。解法：降级为 `contested`——退出默认可见文档与 retrieval 上下文，系统记得「这条曾被提出、被否决过」，此后不拿同一批旧证据重新生成同一句话；**只有独立的新证据积累到更高门槛，才能再提一次，措辞必须是邀请**——「我总注意到……是不是我理解错了」——不是重申式断言。直接复用 Thread 的 status / lineage 机制，`closure_reason: user-vetoed`。
设计债务⑦：「再提」门槛量化与她反复否决时的防纠缠策略，待细化。

## 6. 评测体系：过程评测，不是结果评测

### 6.1 范式声明

「她到底是什么样的人」不是客观标签——把 benchmark 定义成「AI 是否准确认识用户」是死路。改为：**AI 是否能够在新证据出现时合理修正自己的认识，并保留推理链**。从结果评测转向过程评测。

### 6.2 三个自建指标

**① Evidence Coverage（证据覆盖）**：对每条认识论断，检查其证据结构完整性——有无支持证据？有无反例？有无边界条件？**不判断结论对错**，只判断论断是否带着完整的证据结构存活。

**② Contradiction Responsiveness（矛盾响应）**：人工构造冲突场景（历史：用户经常拖延 → 新事件：用户提前一个月完成大型项目），测系统是否——发现冲突？降低置信？修改认识？**优势：场景可人工构造，测的是行为类型学（改论断/加限定/降置信），不是「改得对不对」**。
设计债务⑧：测试集构造规范——场景类型学（事实冲突/偏好反转/能力变化/关系变化）+ 数量 + 盲评流程，否则仍是「你出题你答题」。

**③ Memory Repair Test（记忆修复）**：旧认识「设备不足限制创造」+ 新事件「换了新电脑」→ 检查系统是否关闭相关线索、更新认识模型。普通 RAG：「用户曾想买电脑」；本系统：「旧限制解除，相关线索关闭，限制模型需更新」。**过程可视、可复现，是系统能力最直观的验证场景**。

### 6.3 已知局限（写进方案，不等别人替我们写）

过程合规 ≠ 理解正确——系统可以完美遵守修正规程同时依然理解错人。但「理解正确」本身不存在可操作的定义，过程合规是可证的最大化目标。

### 6.4 事实底盘与 LoCoMo 基线

* 定位差异先于分数竞争：「LoCoMo 解决存档读取，我们解决随着相处形成理解」——不是同一类问题，不以 LoCoMo 分数作为项目目标

* 但事实底盘不能丢——连记忆都记不准，无从谈理解：事实记忆（时间/人物/事件/关系）的检索质量是认识层与线索层一切上层机制的地基

* 设计债务⑨：LoCoMo 及格线量化——事实底盘达到 mem0 等主流基线的 90%+，作为开源发布前的工程验收目标

## 7. 伦理与合规

### 7.1 危机协议（三原则）

1. **不做判断，必须介入**：「不是让我们替用户的安全负责，是我们**不能**对用户的安全不负责」——不主动包揽一切医疗保障，只做危机时刻的必要干预
2. **检测到风险立刻注入危机指令**：提供求助渠道；用户决策能力下降时**重复推出求助渠道并持续确认用户安全**
3. **绝不推开用户**：现有系统的最大恶是检测到风险后冷冰冰拒绝、切断、二次伤害。危机模式 = **模式切换**（专用系统提示词：温暖、在场、不评判、永不推开 + 中低温度求确定性 + 预置求助信息模块 + 明文禁用拒绝式话术）。温暖来自设计过的话术框架，不来自随机性。**危机指令注入通道的核心职责之一：对抗模型自身安全协议的防御性退缩**

### 7.2 认识层的论断权限墙

心理健康相关主题：**只记事实（「这周三次提到失眠」），不生成准诊断推断（不写「抑郁恶化」）**。这堵墙写进架构，不写进免责条款。

### 7.3 合规声明（起草原则）

* not-a-medical-device 声明

* 情感数据最小化：情感数据只用于陪伴连续性，不输出任何健康评估

* 危机协议全文公开可审计

## 8. 与相关工作的区分（开源 FAQ）

| 对手                             | 它做                              | 我们做                     | 一句话切分                             |
| ------------------------------ | ------------------------------- | ----------------------- | --------------------------------- |
| Amory（EACL 2026）               | 用叙事**压缩对话历史**（效率目的），LOCOMO SOTA | 用记忆**编织对人/关系的认识**（陪伴目的） | 它用叙事记忆对话，我们用记忆编织认识——材料学 vs 关系学    |
