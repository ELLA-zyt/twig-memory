# AML 评测机制（流程 / 配额 / 公榜条件 / 基准清单）

> 来源：https://agentmemories.ai/zh-cn/docs §01–§09（2026-09-11 抓取）

## 统一评测边界

参赛方只负责 Add / Search。**回答模型、提示词、评分器、数据集组合、Top K 和汇总规则由平台统一固定**，使榜单分数尽可能反映记忆系统本身的能力。

端到端流程：Add 写入 → 参赛系统持久化/组织/索引 → Search 检索 → 平台统一作答 → 统一评分汇总。

## 准入与评测流程

1. **提交准入申请**：申请新 Key 或为已有 Key 增加版本；填联系人、系统版本、GitHub 仓库或 Add/Search 接口，写清运行方式、Docker 命令、API 封装和原始方法信息
2. **Key 绑定**：审核通过后签发 Leaderboard API Key；新增版本直接绑定原 Key
3. **公开 smoke**：代码提交由平台构建启动；托管接口直接校验。按同步规范执行 Add → Search → Answer → Evaluate 流程
4. **Full 前置检查**：逐项勾选清单——smoke 已通过、API 契约正确、运行说明完整、托管接口可持续 30 天稳定、原创性披露与诚信承诺完成
5. **提交评测任务**：Evaluation 页面验证 Key，选择已绑定版本，填写**唯一 Run Label** 后提交 full
6. **进度与审计**：任务依次执行写入、检索、回答、评分、汇总；页面显示阶段、进度与错误摘要
7. **结果与发布**：结果先仅对绑定 Key 可见；成功 full 进入公榜资格校验与审核队列

**代码审核**：允许复现论文或封装已有仓库，但必须披露原作者、技术报告与方法改动；未披露的重复代码可能被视为抄袭。提示词注入、数据或结果操纵、恶意刷榜均取消资格。

## 评测模式与配额

| 模式 | 用途 | 配额 | 结果 | 公榜 |
|---|---|---|---|---|
| smoke | 独立兼容性测试接口检查同步 Add、Search 和评分链路 | **每小时 1 次** | 仅私有 | 不可发布 |
| full | 固定完整评测套件，进入正式排队、审计、发布 | **每 3 个月 1 次** | 优先私有 | 审核通过后发布 |

> 注：CSIG 公告口径为「同赛道一次 Full 后 30 天冷却、赛期内最多 2 次 Full」，与本文档「每 3 个月 1 次」并存理解——第二期赛期（9-20 ~ 10-31）内实际只有约 1~2 次 Full 机会，**提交前务必用 smoke 和本地彩排把状态调到最佳**。

## 公榜准入条件

- 结果来自成功完成的 full 模式固定套件，所有评测任务均执行成功
- 统一回答模型、评测规范、pipeline code hash、dataset bundle hash 和题量记录完整，与现行发布基线一致
- 结果不得重复提交，通过平台审核

### 文本赛道（7 个）

| 数据集 | 说明 | 本项目经验 |
|---|---|---|
| LoCoMo-Refined | 基于多会话用户历史的长程对话记忆问题 | ✅ 已跑原版 LoCoMo（0.6695，过线） |

| LongMemEval-Refined | 适配平台写入与检索流程的长上下文记忆问答 | ✅ 已跑 LongMemEval-S（0.892） |
| LongMemEval-S | 含证据溯源问题和完整性检查 | ✅ |
| CLBench | 覆盖 0-4k 与 16-32k 区间的上下文学习基准 | ⚠️ 未接触过 |
| PersonaMem-v2 | 长上下文对话与个人偏好的**隐式角色记忆** | ⚠️ 未接触过；但与「用户画像」设计契合 |
| BEAM | 聚焦检索效果与回答质量 | ⚠️ 未接触过 |
