# AML 参赛指南（Participation Guide）

> 来源：https://agentmemoryleaderboard.ai/rules （2026-09-11 抓取，内容为第一期周期示例，第二期时间节点以 CSIG 公告为准）

Agent Memory Challenge 是 Agent Memory Leaderboard 的公开评测周期，面向全球研究者、开源维护者和商业产品团队开放。参赛方提供 Add 和 Search；平台统一运行 Answer、Eval、结果复核与榜单发布。

## 概要

- 参赛免费，无团队规模要求
- 参赛方自行承担 API、数据库、带宽与算力成本；平台承担统一作答、评分与评测编排
- 评测类型：Textual Memory（文本）/ Coding Memory（代码）/ Multimodal（多模态，第二期新增）
- 参赛组别：Academic Methods（学术方法）/ Commercial Products（商业产品），两个维度互相独立

## 第一步：选择评测类型

| 评测类型 | 评测内容 | 可选组别 |
|---|---|---|
| Textual Memory | 事实召回、多跳整合、时序理解、记忆治理、个性化、规则执行、安全与隐私 | 学术方法 / 商业产品 |
| Coding Memory | 从历史工程任务中检索、过滤、复用调试经验、开发经验与项目上下文 | 学术方法 / 商业产品 |

## 第二步：选择参赛路径

第一个动作永远是提交 Evaluation Access Request。Eval Key 不是独立报名步骤，审核通过后签发给自托管 API 的参赛方。

- **Academic · API（自托管 Add/Search）**：提交公开 GitHub 仓库、固定版本、Add/Search 端点、鉴权方式与运行说明。自己运维并保持服务稳定；审核通过后签发 Eval Key。
- **Academic · Code（代码提交，平台部署）**：提交公开 GitHub 仓库 + Docker 启动说明 + Add/Search wrapper + 完整运行文档。平台构建评测，不签发 Eval Key。
- **Commercial · API**：提交固定产品版本、Add/Search 端点、鉴权与容量信息。实现可闭源，结果进商业产品榜。

**开源要求**：学术方法组必须提供公开可核验的 GitHub 仓库，披露原始方法、作者、技术报告及全部改动。商业产品组无需开源，但产品与 API 版本必须稳定可核验。

## 第三步：准备提交材料

申请前先冻结一个明确的评测版本。正式 Full 评测一旦被受理，版本不得因成绩不理想而更换或撤回。

**通用材料**：系统名称与版本、联系方式、组织或团队、评测类型、方法或产品说明、可公开展示的信息、完整提交说明。

**学术方法组**：公开仓库、README、Docker 命令、API 入口、依赖、前人工作署名、方法改动、运行步骤；自托管还需提供公网端点。

**商业产品组**：固定产品版本、Add/Search API、鉴权、专用评测凭证、容量、超时与限流参数。端点须在提交后至少 30 天保持稳定且公网可达。

## 从申请到上榜

1. 提交申请：选评测类型、组别、提交路径，提供固定版本与完整材料
2. 完成接入：自托管方收到 Eval Key；代码提交由平台按 Docker 入口构建
3. 运行 Smoke 与 Full：先验证 Add/Search、鉴权与端到端链路，再进入正式评测
4. 复核与发布：平台复核版本、成绩与合规后发布到对应公开榜单

## 两类密钥（切勿混淆）

| 凭证 | 签发方 | 用途 |
|---|---|---|
| Eval Key / Leaderboard Key | AML 平台 | 验证参赛身份、发起评测、查看私有结果（自托管 API 参赛方才需要） |
| Memory System Key | 参赛方自己 | 允许平台调用参赛方 Add/Search API（接口启用鉴权时提供） |

任何密钥都不得出现在公开仓库、URL、截图、邮件正文或群聊中。

## 有效提交的定义

1. **材料完整**：身份、版本、全部必需材料完整、真实、可核验
2. **Smoke 通过**：Add/Search、鉴权、端到端链路符合现行接入契约
3. **Full 完成**：正式评测与必需任务全部成功，无缺失或重复结果
4. **版本一致**：正式评测所用代码、镜像或 API 与申报版本一致
5. **复核通过**：版本、成绩与合规通过主办方复核

## 核心红线

1. **返回记忆证据**：Search 不得生成最终答案，也不得把答案伪装成记忆记录
2. **保持样本隔离**：禁止跨 user_id、任务、样本或团队共享/检索评测记忆
3. **披露来源与改动**：复用论文、仓库或代码时，注明原作者、技术报告与每项改动
4. **禁止操纵评测**：硬编码、数据泄漏、提示词注入、人工实时答题、结果操纵、恶意刷榜
